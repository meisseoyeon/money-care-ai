# 프론트 준비 상태와 서버 생활비 결과

## 로그인·새로고침 흐름

로그인 요청 중에는 “로그인하고 준비하는 중이에요”를 표시합니다. 백엔드가 초기 준비를 끝내고 토큰을 반환하면 `/demo/me`, 받는 사람, 거래내역과 함께 다음 API를 조회합니다.

- `/baselines/current`: 오늘의 기준 통계.
- `/budget-forecasts/latest`: 현재 입력과 일치하는 생활비 결과.

새로고침으로 로그인 세션을 복원할 때도 두 결과를 확인하기 전에는 송금을 허용하지 않습니다. 브라우저 포커스 복귀와 기존 10초 주기 재조회에서도 준비 상태를 갱신합니다.

## 준비 상태

| 상태 | 화면과 송금 처리 |
|---|---|
| CHECKING | 확인 중 안내, 송금 비활성화 |
| READY | 준비 완료, 기존 동의·금액·받는 사람 검증 후 송금 가능 |
| MISSING | 404: 결과 누락 안내, 재조회·재로그인 제공 |
| STALE | 409 또는 조회 데이터 불일치: 오래된 입력 안내, 송금 비활성화 |
| ERROR | 연결·서버·형식 오류 안내, 송금 비활성화 |

401은 준비 오류로 숨기지 않고 로그인 세션 만료로 처리합니다. 준비 완료 응답이라도 사용자·계좌 잔액·생활비 설정이 다른 조회 결과와 맞지 않으면 현재 결과로 사용하지 않습니다. 생활비 응답의 필수 숫자와 계산식도 검증합니다. 통계 소수점 문자열은 수신한 형태로 보존하며 위험 여부를 판단하지 않습니다.

한국 날짜가 바뀌면 마지막 READY 상태라도 송금을 허용하지 않습니다. 새 결과는 조회 요청에서 만들지 않으므로 “다시 로그인”을 통해 서버 초기 준비를 실행합니다. 이 버튼은 기존 세션을 로그아웃하고 로그인 화면으로 돌려보냅니다. 비밀번호를 저장하거나 자동으로 다시 로그인하지 않습니다.

## 송금 버튼과 실행 보호

- 홈의 돈 보내기 링크는 준비 전 비활성 버튼으로 표시합니다.
- 송금 화면의 “보낼 내용 확인”과 최종 “보내기”를 준비 전 비활성화합니다.
- 공통 `run('transfer')`에서도 준비 상태와 진행 중인 금액 변경 작업을 검사합니다.
- 잔액·설정 변경 작업 중에는 추가 송금을 허용하지 않습니다.
- 확인창을 연 후 잔액·생활비 결과가 달라지면 이전 확인 내용으로 보내지 못하게 하고 다시 확인하도록 안내합니다.
- 백그라운드 재조회가 실패하면 이전 생활비를 현재 결과처럼 보여주지 않습니다.
- 서버에서 이미 성공 응답을 받은 송금은 후속 조회 실패 때문에 실패한 송금으로 표시하지 않습니다. 완료 결과는 유지하고 다음 송금은 준비 상태에 따라 차단합니다.

이는 프론트의 실행 보호입니다. 백엔드 송금 API의 준비 상태 검사와 송금 후 생활비 결과 자동 생성은 별도 작업이며, 프론트 버튼 차단으로 대신하지 않습니다.

## 서버 생활비 결과 표시

홈과 생활비 화면은 서버의 `remaining_days`, `expected_living_cost`, `available_amount`, `shortage_amount`, `as_of`를 표시합니다. API 모드에서 값이 없다고 브라우저 계산으로 대신 채우지 않습니다. 생활비 화면에 서버 계산 결과임을 표시하고 계산 기준 시각을 함께 보여줍니다.

CHECKING·STALE·ERROR이면 이전 금액을 숨기고 준비 안내를 표시합니다. 통계만 누락되고 생활비 결과는 유효한 경우에는 생활비 금액을 보여줄 수 있지만 송금은 막습니다.

송금 직전의 가상 미리보기는 서버의 예상 생활비·예정 지출을 유지하고 보내려는 금액만 여유 금액에서 빼서 계산합니다. 저장된 서버 결과는 수정하지 않습니다. 기존 10만 원 초과 확인 흐름은 유지하고 탐지·알림·AI 로직을 추가하지 않습니다.

현재 백엔드는 송금 후 새 생활비 결과를 자동 저장하지 않습니다. 따라서 송금은 완료되더라도 후속 조회가 409가 되면 준비 필요 상태로 바뀌고, 다시 로그인한 뒤 다음 송금을 할 수 있습니다. 생활비 설정·예정 지출의 저장 API 연결도 기존 담당 작업으로 남겨둡니다.

## 코드 위치

- `frontend/src/features/preparation/api.js`: 조회·상태 분류.
- `frontend/src/features/preparation/state.js`: 날짜·유효 상태·표시 결과 선택.
- `frontend/src/features/preparation/PreparationStatus.jsx`: 공통 안내와 재시도 동작.
- `frontend/src/app/httpApi.js`: 전체 데이터와 준비 결과 연결.
- `frontend/src/app/AppProvider.jsx`: 요청 순서·세션 변경·준비 상태·송금 실행 관리.
- 홈·송금·생활비 화면: 상태에 따른 표시와 버튼 제어.

mock 모드는 기존 시연 데이터와 계산을 유지합니다. 브라우저 저장 키·실행 명령·화면 경로는 유지하고 새 패키지는 설치하지 않았습니다.

## 검증

`frontend`에서 다음 명령을 실행합니다.

```powershell
npm test
npm run build
```

45개 테스트가 API 오류 분류·401 우선 처리·날짜 경계·데이터 불일치·서버 값 유지·미리보기·기존 송금과 mock 동작을 검증합니다. 실제 React 컴포넌트 렌더링 테스트는 상태별 홈 송금 버튼, 준비 안내, 생활비 금액과 기준 시각 표시, 오래된 금액 숨김도 검증합니다.

이번 실행에서는 브라우저 자동화 도구가 초기화 오류로 열리지 않아 실제 브라우저 클릭·시각 검증은 완료하지 못했습니다. 테스트용 API·프론트는 실제 서비스 DB와 분리했으며 실제 송금은 실행하지 않았습니다.
