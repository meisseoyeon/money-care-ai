# 내 돈 안심 · Money Care

React + JavaScript + Vite로 만든 모바일 대응 프런트엔드입니다. 기본값은 **FastAPI 공용 계정 로그인 모드**입니다. 화면에 안내된 `user1 / demo1234!`를 직접 입력해 로그인합니다. 같은 탭의 새로고침에도 로그인은 유지되며 사용자 자동 생성·체험 재시작은 제공하지 않습니다. 공용 계정의 잔액·거래내역·설정은 다른 이용자와 공유합니다. [계정 준비와 실행 방법](../docs/AUTH.md)을 먼저 확인하세요.

기존 8개 화면의 전체 송금·알림 시연은 `frontend/.env.local`에 `VITE_API_MODE=mock`을 지정하여 실행할 수 있습니다. 아래 테스트 계정과 시연 시나리오는 mock 모드용이며 실제 서버 인증과 구분합니다. API 모드에서도 가상 송금과 거래내역은 DB에 연결되어 동작합니다. 모니터링에 동의한 뒤 송금할 수 있으며 탐지·알림 등은 담당 백엔드 기능을 추가 연결해야 합니다.

## 실행하기 (Windows PowerShell)

Node.js 22.12 이상 또는 Node.js 24를 설치한 뒤 저장소 루트에서 실행하세요. Python 가상환경은 필요하지 않습니다.

```powershell
cd frontend
npm ci
npm run dev
```

터미널에 표시되는 주소(기본 http://localhost:5173)를 브라우저에서 엽니다. 다른 프로그램이 포트를 쓰면 Vite가 다른 포트를 선택합니다. 종료는 Ctrl+C입니다.

```powershell
npm test
npm run build
npm run preview
```

build 결과는 dist/입니다. preview는 빌드 결과 확인용입니다. HashRouter를 사용하므로 주소는 /#/alerts 같은 형태입니다. index.html 파일을 직접 더블클릭하지 말고 웹 서버로 실행하세요.

## 화면 8개

| 화면 | 주소 | 구현 기능 |
|---|---|---|
| 로그인 | /#/login | 테스트 계정 선택, 비밀번호 표시, 더미데이터 초기화 |
| 홈 | /#/ | 현재 잔액, 생활비 예측, 최근 거래·알림 |
| 송금 | /#/transfer | 받는 사람 선택, 금액 입력, 확인·완료 팝업 |
| 거래 내역 | /#/transactions | 입금·출금 필터, 더 보기, 거래 상세 펼치기 |
| 알림 목록 | /#/alerts | 미응답 필터, 알림 상세 이동 |
| 알림 상세 | /#/alerts/:id | 쉬운 설명, 판단 근거, 응답 3개, 대응 안내·공유 철회 |
| 생활비 계획 | /#/budget | 수입일·예정 수입·하루 생활비, 예정 지출 추가·수정·납부·취소 |
| 지원자 | /#/supporter | 공유받은 알림·설명·안내만 확인 |

공통 설정 팝업에 모니터링 켜기/끄기, 준비된 지원자 연결 해제/재연결, 로그아웃이 있습니다. 안내와 지원자 상세는 기존 화면에 통합해 별도 페이지를 늘리지 않았습니다.

## 테스트 계정

| 계정 | 이메일 | 비밀번호 |
|---|---|---|
| 당사자 A · 서연 | user-a@example.test | moneycare123! |
| 당사자 B · 민지 | user-b@example.test | moneycare123! |
| 지원자 · 이지원 | supporter@example.test | moneycare123! |

당사자마다 30일 거래 90건, 잔액 800,000원, 다음 수입일 20일 뒤, 하루 생활비 20,000원, 예정 지출 150,000원이 생성됩니다. 과거 거래 잔액과 현재 잔액은 이어집니다. A에게만 지원자가 연결되어 있습니다. B로는 사용자 간 데이터 분리와 지원자 미연결 상황을 확인할 수 있습니다.

### 시연 순서

1. 당사자 A 선택 → 로그인. 홈의 여유 금액 250,000원을 확인합니다.
2. 송금 → 처음 보내는 김하늘 → 30만 원 → 보낼 내용 확인 → 큰 금액·생활비 부족 경고 → 확인했어요 → 최종 확인 → 보내기. 경고에서 도움 요청만 하면 송금은 실행되지 않습니다.
3. 잔액 500,000원과 큰 송금 알림을 확인합니다. 생활비 부족 50,000원 알림도 목록에 별도로 생성됩니다.
4. 알림 상세 → 잘 모르겠어요 → 기본 대응 단계 표시.
5. 도와주세요 → 공유 확인. 설정에서 로그아웃합니다.
6. 지원자 로그인 → 공유받은 알림과 안내를 확인합니다.
7. A로 다시 로그인 → 해당 알림의 공유 철회. 지원자에게 더 이상 표시되지 않습니다.

평소 상대 박민수에게 10,000원을 보내면 정상 거래로 저장되고 새 알림은 생성되지 않습니다. 큰 송금과 새 상대 규칙을 동시에 충족해도 거래 알림은 한 건으로 합쳐집니다. 부족 알림은 사용자별 하루 한 건이며 생성 당시 근거를 유지합니다.

## 폴더 구조

```text
src/
  main.jsx                       앱 시작
  app/
    App.jsx                      역할별 라우팅
    AppProvider.jsx              로그인·전체 데이터·재조회 상태 관리
    Layout.jsx                   공통 메뉴·앱 레이아웃
    api.js                       실제 API / mock 선택
    httpApi.js                   기능별 API 조합
  features/
    auth/                        로그인 화면·세션 관리
    home/                        홈 화면
    transfers/                   송금 화면·사전 확인 계산·API
    transactions/                거래내역 화면·페이지 조회 API
    alerts/                      알림 목록·상세·대응 안내·문구·API
    budgets/                     생활비 화면·예측 계산·API
    supporters/                  지원자 화면·연결·공유 API
    settings/                    설정 모달·모니터링 설정 API
  shared/
    ui/UI.jsx                    공통 버튼·카드·모달
    api/httpClient.js            HTTP·토큰 헤더·타임아웃·오류 처리
    state/AppContext.js          공통 Context와 useApp 훅
    lib/                         날짜·금액·표시·오류·통계·저장 키
    styles/global.css            전역·반응형 스타일
  mocks/
    mockApi.js                   브라우저 시연 API
    fixtures.js                  시연 계정·더미데이터
tests/                          로그인·API·mock·송금 검증 28개
```

각 기능 폴더에 관련 화면, 계산 함수, API 호출을 함께 둡니다. `app`은 기능들을 연결하고, `shared`는 특정 기능에 의존하지 않는 코드만 둡니다. 화면에서 공유 상태를 읽을 때는 `shared/state/AppContext.js`의 `useApp`을 사용하고, 데이터 변경과 재조회 처리는 `app/AppProvider.jsx`에서 관리합니다. 기능별 API는 request 함수를 전달받으므로 공통 HTTP 구현과 분리됩니다.

기존 `/#/login`, `/#/transfer` 등의 화면 주소와 `npm run dev` 실행 방법은 유지합니다. mock 데이터 형식·브라우저 저장 키도 그대로 사용합니다. 백엔드 API 계약은 [API_CONTRACT.md](../docs/API_CONTRACT.md)를 참고하세요.

## FastAPI 연결

### 송금 전 확인

10만 원을 초과하는 송금은 경고 팝업을 먼저 표시하고, 사용자가 확인한 다음 `보낼 내용 확인` 팝업으로 이동합니다. 송금 후 예상 잔액으로 생활비가 부족해지는 경우 부족 금액도 함께 표시합니다. 정확히 10만 원인 경우에는 기존 확인 팝업으로 이동합니다.

경고의 `도움 요청하기`는 공유할 내용을 한 번 더 확인한 뒤 연결된 지원자에게 송금 예정 내용을 공유합니다. mock 모드에서는 공유만 저장하고 거래나 잔액은 변경하지 않습니다. 실제 송금은 최종 `보내기`를 눌렀을 때만 실행됩니다. API 모드의 `/transfer-help-requests`는 백엔드 구현이 필요한 제안 경로입니다. 현재 DDL은 송금 전 도움 요청을 위한 별도 모델/저장 정책을 정의하지 않으므로 서버 설계 시 함께 정해야 합니다.

기본 데이터에서 30만 원을 선택하면 큰 금액과 생활비 5만 원 부족 경고를 함께 확인할 수 있습니다.

```powershell
Copy-Item .env.example .env.local
```

.env.local을 아래처럼 수정하고 개발 서버를 재시작합니다.

```dotenv
VITE_API_MODE=api
VITE_API_BASE_URL=http://localhost:8000
```

**현재 백엔드는 `/auth/login`, `/auth/me`, `/auth/logout`과 공용 계정의 가상 송금·거래내역을 제공합니다.** 로그인 시 데이터는 생성하거나 초기화하지 않습니다. [공용 계정 로그인 안내](../docs/AUTH.md)와 [API 계약](../docs/API_CONTRACT.md)을 참고하세요.

탐지·LLM·RAG·Airflow는 서버 담당입니다. 브라우저에 Gemini 키나 DB 접속 정보를 넣지 마세요. API 모드의 생활비 예측은 /budget-forecasts/latest 결과를 표시하며 브라우저에서 Airflow를 실행하지 않습니다.

## 동작 범위

- 더미데이터는 localStorage에, 로그인 상태는 탭별 sessionStorage에 저장합니다. 새로고침해도 유지되며 로그인 화면에서 전체 초기화할 수 있습니다.
- mock 모드의 로그인·권한 구분은 UI 시연용입니다. 실제 인증·당사자 권한·공유 철회·중복 송금 방지·잔액 갱신 트랜잭션은 서버에서 검증해야 합니다.
- 안내는 검토 가능한 고정 문구(FALLBACK)이며 Gemini나 벡터 검색을 호출하지 않습니다. 가짜 출처는 표시하지 않습니다. API 모드는 서버가 반환한 단계와 출처를 표시합니다.
- 평소 지출 p95는 초기 정상 거래로 계산하고 고정합니다. 합성 데이터에서 큰 송금·새 상대 탐지를 재현하기 위한 로직이며 실제 사기 확률이 아닙니다.
- 데이터는 10초마다, 탭 재진입 시 재조회합니다. 공유 철회 반영은 재조회 시점 기준이며 실시간 푸시는 없습니다.
- 수입일이 지나면 테스트 데이터를 초기화해 주세요. mock의 날짜 계산은 브라우저 시간대 기준이며 실제 서버는 Asia/Seoul 기준을 합의해야 합니다.
- API 어댑터는 거래내역의 next_cursor를 따라 모든 페이지를 수집합니다. 화면에서는 15건씩 더 볼 수 있습니다.
- 예정 지출 삭제는 이력 보존을 위해 CANCELLED로 처리합니다. 지원자 초대·회원가입·실제 은행 송금·관리자 화면은 범위에 포함하지 않습니다.
- 모니터링을 끄면 이 시연에서는 가상 송금을 막습니다. 실제 서비스의 동의 철회 정책은 별도로 정해야 합니다.

## 검증

npm test는 잔액 연속성, 중복 요청, 동시 송금 잔액 초과, 새 상대 판단, 사용자 분리, 공유 범위·철회 등을 검증합니다. 실제 PostgreSQL 동시성이나 FastAPI 보안을 검증하는 테스트는 아닙니다.
