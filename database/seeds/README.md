# 공용 계정 초기 데이터

`user1.sql`은 `user1 / demo1234!` 계정, 계좌, 생활비 설정, 예정 지출 2건, 정상 거래 30건을 한 트랜잭션으로 준비합니다. 로그인이나 서버 시작 때 자동 실행하지 않습니다.

## 적용

저장소 루트의 PowerShell에서 실행합니다. Flyway V6까지 먼저 적용합니다.

```powershell
docker compose -f .\compose.yaml up -d --wait db
docker compose -f .\compose.yaml run --rm flyway migrate
Get-Content -Raw -Encoding UTF8 .\database\seeds\user1.sql | docker compose -f .\compose.yaml exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

## 데이터 규칙

| 구분 | 건수 |
|---|---:|
| 수입 | 1 |
| 식비 | 10 |
| 교통비 | 7 |
| 소액 구매 | 4 |
| 평소 상대 송금 | 8 |
| 합계 | 30 |

- 버전 `normal-v1`, seed `42`의 고정 패턴입니다. seed와 거래 순번의 MD5에서 작은 금액·시간 변화를 계산하며 DB의 전역 난수 상태를 사용하지 않습니다.
- 기준 시각은 최초 SQL 실행 트랜잭션의 `CURRENT_TIMESTAMP`입니다. 시각 배치는 Asia/Seoul 기준이며 저장은 TIMESTAMPTZ입니다. 같은 버전·seed·기준 시각이면 같은 내용이 생성됩니다.
- 모든 거래는 기준 시각 이전 30일 안에 있고, 수입은 10일 전입니다. 기준 시각·시작 잔액·목표 잔액·건수를 `demo_seed_metadata`에 저장합니다.
- 시작 잔액은 `800000 - (총입금 - 총출금)`으로 역산합니다. 매 거래에 입출금을 순서대로 반영하며 중간 음수 잔액과 시각 역전을 검사합니다. 마지막 계산 결과와 계좌 잔액은 모두 800,000원입니다.
- 생활비는 하루 20,000원, 다음 수입은 기준 한국 날짜의 20일 뒤, 예상 수입 1,000,000원입니다. 기존 생활비 설정은 보존합니다.
- 예정 지출은 월세 100,000원(5일 뒤), 통신비 50,000원(10일 뒤)입니다. 같은 제목의 예정 지출이 이미 있으면 추가하지 않습니다.
- 평소 상대는 demo-payee-1~4이며 각각 2건씩 송금합니다. demo-payee-5~6은 초기 이력에 없습니다. 송금 화면의 친숙 여부는 로그인 사용자의 실제 송금 이력에서 계산합니다.
- 초기 거래는 `source=SYNTHETIC`, `scenario_label=NORMAL`입니다. label은 평가용이며 사용자 API 응답과 탐지 특징에 포함하지 않습니다. 이 SQL은 탐지·알림을 생성하지 않습니다.
- 모니터링 동의는 대신 입력하지 않습니다. 송금은 사용자가 로그인 후 내 설정에서 동의하고 켠 뒤 이용합니다.

## 재실행과 실패

- 정상 적용된 메타데이터와 초기 거래 30건이 있으면 SQL을 다시 실행해도 전체 초기화를 하지 않습니다. 사용자가 추가한 송금, 변경된 잔액·설정·동의·비밀번호를 보존합니다.
- 초기 데이터 메타데이터 없이 이미 거래가 있거나 잔액이 바뀌어 있으면, 이력을 임의로 끼워 넣거나 덮어쓰지 않고 오류로 중단합니다.
- 잘못된 메타데이터나 불완전한 초기 이력이 발견돼도 오류로 중단합니다. 버전 변경을 이유로 과거 이력을 자동 교체하지 않습니다.
- 실패하면 계정·계좌·설정·예정 지출·거래·메타데이터의 이번 변경 전체가 롤백됩니다.
- 다른 계정 데이터는 수정하지 않습니다. 모든 데이터는 합성 데이터이며 실제 은행 송금이 아닙니다.
